# 보안 설계 — hilgpu.com

요구사항: **hilgpu.com에 접속한 누구도 데스크톱이나 연구실 서버에 도달할 수 없어야 한다.**

이 문서는 그 요구사항을 어떤 구조로 만족시키는지, 그리고 각 방어가 무엇을 막는지 적어둔 것입니다.

---

## 1. 왜 터널이 아니라 단방향 push인가

처음 검토한 Cloudflare Tunnel은 이 요구사항에 **부적합**합니다.

```
[방문자] → hilgpu.com → Cloudflare → cloudflared 터널 → 127.0.0.1:8899 (내 데스크톱)
                                                        ↑ 경로가 존재한다
```

터널은 인바운드 포트를 열지 않지만, 공개 호스트네임에서 데스크톱 프로세스까지 **살아 있는 요청 경로**가 존재합니다. `hilmon.py`에 파싱 버그나 경로 처리 실수가 하나라도 있으면 그것이 인터넷에 노출됩니다. "절대 도달 불가"라는 요구사항과 맞지 않습니다.

채택한 구조는 경로 자체를 없앱니다.

```
[데스크톱]                                  [Cloudflare Pages]        [방문자]
hilmon.py --publish  ──(HTTPS PUT, 아웃바운드)──▶  정적 index.html   ◀── hilgpu.com
   │                                              + status.json
   └─ SSH(아웃바운드) → hi14 … hi30

방문자 → 데스크톱 : 경로 없음
방문자 → 연구실 서버 : 경로 없음
```

- 데스크톱은 **리스닝 소켓을 인터넷에 열지 않습니다.** 방화벽 인바운드 규칙 변경 0건.
- 공개 사이트는 **정적 파일**입니다. 실행되는 코드도, 백엔드도, DB도 없습니다.
- Pages 호스트가 완전히 장악되어도 공격자가 얻는 것은 **GPU 사용률 숫자**뿐입니다. 자격증명도, 내부 주소도, 데스크톱으로 가는 통로도 없습니다.
- 데이터는 한 방향으로만 흐릅니다. 업로드는 데스크톱이 **시작**하며, 그 커넥션으로 되돌아오는 요청은 존재하지 않습니다.

## 2. 내보내지 않는 것 (`public_mode`)

앞단 인증은 이미 서비스된 데이터를 되돌리지 못합니다. 그래서 민감한 값은 **애초에 페이로드에 넣지 않습니다.** `hilmon.py`의 `redact()`가 프로세스를 떠나기 전에 제거합니다.

| 항목 | 내부(`public_mode: false`) | 공개(기본값) |
|---|---|---|
| GPU util / mem / power / temp / fan | O | **O** ← 페이지의 목적 |
| load, RAM, 디스크, uptime | O | O |
| 서버 이름 (`hi14`), GPU 모델, 위치 | O | O |
| **호스트 IP / SSH 포트** | O | **제거** |
| **관리자 이름** | — | **저장조차 안 함** |
| **프로세스 소유자 로그인명** | O | **제거** |
| **PID, 프로세스 이름** | O | **제거** |
| **SSH 에러 원문** | O | **`unreachable`로 대체** |

익명화에 대한 판단: 이니셜(`한··`)이나 로그인명 해시는 **익명이 아닙니다.** 연구실 인원이 18명 수준이므로 명부와 대조하면 즉시 역추적됩니다. 그래서 이름에서 파생된 어떤 형태도 내보내지 않고, 프로세스는 `job 1 · 22G`처럼 **개수와 메모리**로만 표시합니다. "이 GPU에 누가 있다"는 알 수 있고 "누구인지"는 알 수 없습니다.

SSH 에러 문자열도 조용한 유출 경로입니다. `ssh: connect to host 203.0.113.21 port 7777: Connection refused`는 IP와 포트를 그대로 노출하므로 상태별 고정 문구로 치환합니다.

> 검증됨: 합성 데이터에 `147.46.*`, `7777`, 실명, 로그인명, 원본 에러를 심어두고 서비스된 페이로드를 검사 → 유출 0건.

## 3. 수집기 자체의 최소 권한

공개 경로가 없더라도 데스크톱의 SSH 키는 여전히 가치 있는 표적입니다.

- **바인딩 기본값이 `127.0.0.1`.** `0.0.0.0`이 아닙니다. 실수로 캠퍼스 네트워크에 노출되지 않습니다.
- **읽기 전용 강제 명령 키를 쓰십시오.** 각 서버의 `~/.ssh/authorized_keys`에 모니터링 전용 키를 등록할 때:

  ```
  command="/usr/local/bin/hil-metrics",restrict PUBKEY_HERE
  ```

  `/usr/local/bin/hil-metrics`는 `nvidia-smi` 조회만 수행합니다. 이렇게 하면 키가 유출되어도 **셸을 얻을 수 없고**, 포트 포워딩·에이전트 포워딩·PTY가 모두 차단됩니다(`restrict`). 얻을 수 있는 건 이미 대시보드에 있는 숫자뿐입니다.
- **패스워드 인증 사용 안 함.** `BatchMode=yes`로 프롬프트 자체를 차단합니다. 자격증명은 키뿐이며 스프레드시트의 공용 비밀번호는 이 시스템 어디에도 쓰이지 않습니다.
- **커넥션 다중화.** `ControlMaster` + `ControlPersist=300`으로 5분에 한 번만 핸드셰이크합니다. 14대를 5초 주기로 폴링해도 초당 2.8 exec 채널이며, 캠퍼스 SSH 레이트 제한(초당 60) 대비 충분한 여유를 둡니다.

## 4. 페이지 자체의 방어

정적 페이지라도 방어는 넣어둡니다.

- **CSP `default-src 'none'`** — 외부 스크립트·폰트·이미지·XHR 전부 차단. 이 페이지는 외부 요청이 0건이므로 CSP를 최대로 좁힐 수 있습니다. `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`.
- `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`로 geolocation·카메라·마이크 차단, `Cross-Origin-Opener-Policy`/`Resource-Policy: same-origin`, `Strict-Transport-Security` 2년.
- **`<meta name="robots" content="noindex, nofollow, noarchive">`** — 검색엔진 색인 및 캐시 방지.
- **정적 라우트는 화이트리스트 확장자만** 서비스하고, 해석된 경로가 `web/` 밖이면 404. `../`, URL 인코딩된 `%2e%2e`, 절대 경로, 소스 파일 요청 전부 404로 검증했습니다.
- **DOM 텍스트는 `textContent`로만** 씁니다. 첫 페인트 이후 `innerHTML`을 쓰지 않으므로 서버 데이터가 마크업으로 해석될 경로가 없습니다.

## 5. 남은 위험과 권고

1. **페이지가 인증 없이 공개됩니다.** 익명화 후에도 "hi28이 8장 만실"은 연구실 운영 정보입니다. 최소 방어로 **Cloudflare Access**를 걸어 `@snu.ac.kr` 계정만 허용하십시오(무료, 정적 사이트 앞단에서 동작, 데스크톱과 무관). 설정법은 `DEPLOY-hilgpu.com.md` 참조.
2. **엑셀 파일을 이 배포 근처에 두지 마십시오.** `HIL 서버관리현황.xlsx`에는 출입문 비밀번호와 일부 서버의 평문 비밀번호가 들어 있습니다. 저는 이 파일에서 서버 이름·IP·GPU 구성만 읽었고, 비밀번호 규칙은 사용하지 않았습니다. 이 파일은 리포지토리·업로드 디렉터리에 절대 포함시키지 마십시오.
3. **`servers.json`은 내부 IP 목록입니다.** 업로드 대상 디렉터리에 들어가지 않습니다(`--publish`는 `index.html`과 `status.json`만 씁니다). 공개 git 리포지토리에 올리지 마십시오.
4. **로고 사용**: SNU 엠블럼은 학교 상표입니다. 연구실 내부용은 통상 문제 없지만, 공개 도메인에 게시하는 것은 학과와 확인해 두는 편이 안전합니다.
